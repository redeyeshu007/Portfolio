# Freelancing as a Student Developer: What I Learned

Writing code for a grade and writing code for a paying client are two different jobs. Freelancing while still a student taught me the second one — the part nobody tests you on.

## What actually mattered

- **Requirements are never complete.** The client's first brief is a starting point, not a spec. Asking questions early saved every project.
- **Communication beats code.** A clear weekly update prevented more problems than any clever architecture.
- **Deadlines are promises.** Missing one quietly is worse than flagging a delay loudly and early.

## The hard lessons

- Underquoting a project because I underestimated "the last 10%" — which is always 50%.
- Saying yes to scope creep instead of having an honest conversation about it.
- Shipping something that *worked on my machine* and learning what "production-ready" really means.

## Why it was worth it

Real clients gave me real constraints, and constraints make you a better engineer. I learned to deliver, not just to build — and that's the difference between a hobby and a craft.
