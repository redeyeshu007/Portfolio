# How I Built My Portfolio Website

A portfolio is the one project where you're both the developer and the client — and the client is impossible to please. Here's how I built mine, and the decisions behind it.

## The stack

- **Next.js** for fast, SEO-friendly pages and a clean routing model.
- **Tailwind CSS** for a consistent design system without fighting CSS.
- **MDX** so blog posts are just files — write in Markdown, drop in components when needed.

## Design decisions

- **Content first.** The work and the writing lead; animations support, never distract.
- **Dark and light modes** that both actually look intentional.
- **Speed as a feature.** Every image and font is optimized; the page should feel instant.

## Challenges

- Keeping the blog easy to update — MDX with a typed schema solved this.
- Balancing personality with professionalism so recruiters *and* peers feel at home.
- Resisting the urge to add features no one asked for.

## Wrap-up

The best portfolio isn't the flashiest — it's the one that clearly shows *what you've built and why it mattered*. This site is built to do exactly that, and to keep evolving as I do.
