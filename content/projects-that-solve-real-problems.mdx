# Building Projects That Solve Real Problems

There's a graveyard of to-do apps and weather widgets on every developer's GitHub. I used to add to it. Then I started asking a different question before writing any code: *whose problem does this solve?*

## Tutorial projects vs. real projects

- A **tutorial project** ends when it matches the video. A **real project** ends when someone can use it.
- Tutorials hand you the requirements. Real problems make you *discover* them.
- Copying a build teaches syntax. Solving a problem teaches engineering.

## My process

1. **Find a real pain** — mine, a client's, or a community's.
2. **Talk to whoever has it** before building anything.
3. **Ship the smallest useful version**, then improve based on real use.
4. **Measure** whether it actually helped.

## Why it matters

Every project I'm proud of — meeting AI, log monitoring, accessibility tools — started from a genuine problem, not a tutorial. <mark>Problem-solving is the skill; the tech stack is just the tool.</mark> Recruiters notice the difference, but more importantly, so do users.
